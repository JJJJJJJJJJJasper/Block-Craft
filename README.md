# BlockCraft

A multiplayer voxel sandbox game that runs in the browser. It's built for a school Chromebook,
so it needs no installs and has a light GPU budget. You can share one link and your friends join the same world.
All textures and sounds are generated by code at startup; there are no image or audio files.

> **Renaming the game:** change `GAME_NAME` in `shared/config.js`. The menu, the page title and the server log all use it.

---

## Features

- **Infinite procedural worlds** made of 16×16×128 chunks. Each world has a seed and five biomes (plains, forest,
  desert, snowy tundra, hills), plus caves, ores at realistic depths (coal, iron, gold, diamond), trees, cactus,
  flowers, oceans and lakes you can swim in, and a bedrock floor.
- **Fast rendering:** Web Workers generate, light and mesh chunks. Hidden faces are culled and identical
  neighbouring faces are merged (greedy meshing), with ambient occlusion. All textures share one atlas
  (a WebGL2 texture array), there's frustum culling, fog, and a render distance from 2 to 12 chunks.
- **Lighting and time:** a day/night cycle with sun, moon, stars and sky colours. Skylight and torch light are
  computed per block, so caves are dark and torches glow warm.
- **Blocks and items:** 38 blocks, sticks, coal, ingots, diamonds, food, and 20 tools (wood, stone, iron, gold and
  diamond pickaxes, axes, shovels and swords). Tools have mining speeds and durability.
- **Interaction:** a block outline, hold-to-break with crack stages, placing, a 9-slot hotbar, an inventory (E),
  item drops you can pick up, and a 2×2 crafting grid, 3×3 crafting table and furnace smelting.
- **Survival:** health, hunger, fall damage, drowning, death (you drop your items) and respawning.
  **Creative:** infinite blocks, flying and instant breaking.
- **Mobs:** pigs wander and flee when hit. Zombies come out at night, chase survival players and burn in sunlight.
- **Procedural audio:** break, place, footsteps, hurt, pickup, eating and mob sounds. Press M to mute.
- **Multiplayer:** the server is authoritative. It handles rooms with 4-letter codes, invite links
  (`/?world=ABCD`), interpolated avatars with name tags, chat (T), a player list (Tab), host controls
  (game mode, time, kick) and automatic reconnects.
- **Persistence:** each world's edits, players, inventories and furnaces are saved to `data/<CODE>.json`.
  Saves happen every 30 s and on shutdown.
- **Anti-cheat checks:** limits on reach and movement speed, and rate limits on edits and chat.

## 1. Run it on your own computer

You need **Node.js 18 or newer** (https://nodejs.org, the "LTS" version).

```bash
npm install        # download the libraries (three.js, ws, vite) - once
npm run dev        # start the game in development mode (auto-reloads when you edit code)
```

Open **http://localhost:3000** in Chrome, type a name and click **Create World**.

For production mode (faster loading, which is what hosting sites run):

```bash
npm run build      # bundle the client into dist/
npm start          # serve dist/ + run the game server
```

Use the `PORT` environment variable to pick a different port, e.g. `PORT=8080 npm start`.

### Let friends on the same Wi-Fi join

1. Start the server on your computer (`npm run dev` or `npm start`). It prints something like:
   ```
   Local:   http://localhost:3000/
   Network: http://192.168.1.23:3000/
   ```
2. Create a world and press **Esc**. The pause menu shows the **world code**.
3. Your friends open `http://192.168.1.23:3000/?world=ABCD` on their Chromebooks, using *your* Network
   address and code.

If it doesn't connect:
- **Windows:** allow Node.js through the firewall when asked (or in *Windows Defender Firewall → Allow an app*).
- **macOS:** click *Allow* when asked about incoming connections.
- **School/public Wi-Fi** often blocks devices from talking to each other ("client isolation"). In that case,
  deploy online (next section) or use a phone hotspot.

## 2. Put it online for free (Render)

Render's free web services support WebSockets, which this game needs.

**Step 1 - Put the code on GitHub**
1. Create a free account at https://github.com and click **New repository** (e.g. `blockcraft`). Leave it empty.
2. In this project folder run:
   ```bash
   git init            # skip if it's already a git repo
   git add -A
   git commit -m "BlockCraft"
   git branch -M main
   git remote add origin https://github.com/YOUR-NAME/blockcraft.git
   git push -u origin main
   ```

**Step 2 - Deploy on Render**
1. Create a free account at https://render.com (sign in with GitHub).
2. Click **New + → Blueprint**, pick your `blockcraft` repository and click **Apply**.
   Render reads `render.yaml` from this project and sets everything up.
   *Or create it by hand:* **New + → Web Service** → pick the repo, then set
   - Runtime: **Node**
   - Build Command: `npm install && npm run build`
   - Start Command: `npm start`
   - Instance Type: **Free**
3. Wait for the build (2-4 minutes). Render shows your URL, like `https://blockcraft-abcd.onrender.com`.
4. Open it, create a world, press **Esc → Copy invite link**, and send the link to your friends.

**Important things to know about the free plan**
- The server **goes to sleep after ~15 minutes with nobody connected**. The next visitor waits about a minute while it wakes up.
- Free instances have **no permanent disk**. Saved worlds are lost whenever the server restarts, sleeps or
  redeploys. Worlds survive while people are playing, and the menu offers to recreate a missing world code
  with a fresh map. To keep worlds permanently, switch the service to a paid instance and attach a
  **Disk** (instructions are in the comments of `render.yaml`), then set `DATA_DIR` to the disk's mount path.

### Alternative: Railway

1. Push to GitHub as above, then at https://railway.com click **New Project → Deploy from GitHub repo**.
2. Railway detects Node and runs `npm install`, `npm run build` and `npm start` automatically.
3. Under **Settings → Networking**, click **Generate Domain** to get a public URL.
4. To keep worlds: right-click the service → **Attach Volume**, mount it at `/data`, and add the variable
   `DATA_DIR=/data`.
   (Railway gives trial credit; after that it's a low-cost paid plan. Check their pricing page.)

## Controls

| Key | Action | Key | Action |
| --- | --- | --- | --- |
| WASD | Move | Mouse | Look |
| Space | Jump / swim up | Space twice | Toggle flying (creative) |
| Shift | Sprint (descend when flying) | W twice | Sprint |
| Left click (hold) / **R** | Break block / attack | Right click / **F** | Place block / use table/furnace / eat |
| 1-9, mouse wheel | Choose hotbar slot | E | Inventory and crafting |
| Q | Drop one item | T or / | Chat (host commands start with /) |
| Tab | Player list | F3 or ` | FPS / debug info |
| M | Mute | Esc | Pause menu (settings, invite link, host controls) |

**Chromebook tips**
- The top-row keys are browser keys (F3 = refresh!). Use **`** for the debug screen, or hold **Search** for F-keys.
- Trackpad: **tap** = break/attack, **two-finger tap** or **Alt + tap** = place. You can also use **R** to break and **F** to place.
- Ctrl is deliberately unused, because Ctrl+W closes the tab.
- If it's slow, lower the render distance in **Esc → Settings** (4 is a good value for older Chromebooks).
  Leave "Sharp rendering on high-DPI screens" off.

**Host commands** (the first player in a world is the host; also available in Esc → Host):
`/time day|noon|sunset|night`, `/mode survival|creative`, `/kick <name>`.

## Crafting cheat sheet

| Recipe | Result |
| --- | --- |
| 1 Wood Log (anywhere) | 4 Planks |
| 2 Planks stacked vertically | 4 Sticks |
| 2×2 Planks | Crafting Table |
| Coal above a Stick | 4 Torches |
| 8 Cobblestone in a ring (3×3 table) | Furnace |
| 3 material on top, 2 sticks down the middle (3×3) | Pickaxe |
| 2 material + 1 beside, 2 sticks (3×3) | Axe |
| 1 material, 2 sticks below | Shovel |
| 2 material, 1 stick below | Sword |
| 2×2 Stone | 4 Bricks |
| 2×2 Sand | Sandstone |
| 2×2 Leaves | White Wool (placeholder until sheep exist) |
| White Wool + flower / cactus / ice / coal | Coloured wool |

Tool materials are planks, cobblestone, iron ingot, gold ingot or diamond.
**Furnace:** put iron/gold ore, sand, cobblestone, a wood log or raw porkchop in the top slot and fuel
(coal, wood, planks, sticks) in the bottom slot.

All recipes live in `shared/recipes.js`.

## How the code is organised

```
shared/     Code used by BOTH the browser and the server
  config.js     every tunable number + GAME_NAME
  blocks.js     block definitions (add new blocks here)
  items.js      tools, food, materials, mining-speed formula
  recipes.js    crafting + smelting recipes
  noise.js      seeded random numbers + simplex noise
  terrain.js    the world generator (pure function of seed + chunk position)
  physics.js    box-vs-blocks collision
  raycast.js    "which block am I looking at"
  chunk.js      chunk coordinate helpers
  protocol.js   list of network messages
server/
  index.js        HTTP + WebSocket server, game loop, autosave
  room.js         one world: validation, broadcasting, items, furnaces, host controls
  serverWorld.js  chunk cache + the list of player edits
  mobs.js         pig and zombie AI
  persistence.js  save/load JSON files in data/
client/
  index.html, style.css, main.js
  engine/     game.js (main loop), player.js (movement), input.js
  world/      world.js (chunk streaming), worker.js, workerPool.js, mesher.js, lighting.js
  rendering/  renderer.js (Three.js + chunk shader), textures.js (procedural art), sky.js, entities.js
  ui/         menu.js, hud.js, inventory.js, chat.js, settings.js
  net/        network.js (WebSocket + reconnect)
  audio/      sfx.js (Web Audio sound synthesis)
test/sync-test.js   automated multiplayer test
```

### The big ideas (worth reading in this order)

1. **`shared/terrain.js`:** noise functions turn into landscapes. Each column's height mixes a slow
   "continent" noise with detail noise, scaled by a "hilliness" noise. Caves are where two 3D noise fields
   are both near zero. Because the generator is a *pure function* of the seed, the browser and the server
   produce identical chunks. The network only ever sends **edits** (which blocks players changed), never terrain.
2. **`client/world/mesher.js`:** face culling and greedy meshing reduce ~200,000 possible faces per chunk to a
   few hundred rectangles.
3. **`client/world/lighting.js`:** light spreads by breadth-first search, like a flood fill.
4. **`client/rendering/renderer.js`:** the shader computes `max(skylight × daylight, torchlight)`, so the
   day/night cycle costs nothing.
5. **`server/room.js`:** the server decides what really happened. Clients *ask* to break or place, and the
   server checks the request and tells everyone.
6. **`client/rendering/entities.js`:** other players are drawn 100 ms in the past and interpolated between
   network snapshots, so they move smoothly even though updates only arrive 20 times a second.

### Adding a new block

1. Add an entry to `BLOCK_LIST` in `shared/blocks.js` with an unused `id` (below 256):
   ```js
   { id: 40, name: 'mossy_stone', tex: { all: 'mossy_stone' }, hardness: 1.5, tool: 'pickaxe', harvest: 1, sound: 'stone' },
   ```
2. Add a painter with the same texture name in `PAINTERS` in `client/rendering/textures.js`:
   ```js
   mossy_stone(img, r) { PAINTERS.stone(img, r); speckle(img, hex('#4a7a2a'), 0.25, r); },
   ```
   (Or tint the wool pattern with `tex: { all: 'wool:#hexcolor' }` and skip this step.)
3. Optionally add a recipe in `shared/recipes.js`. The block shows up in the creative inventory automatically.

## Testing

```bash
npm test
```

This starts the real server with a temporary data folder and connects two headless clients. It then checks
that placed and broken blocks reach the other player, late joiners receive edits, out-of-reach edits are
rejected, chat and movement sync, and an edit survives a server restart.

## Known limitations

- **Inventories are client-side.** The server saves your inventory but doesn't verify it, so a determined player
  could edit their own items. Reach, speed and edit rate *are* enforced, and furnace contents and dropped items
  are server-owned.
- Water doesn't flow, and sand and gravel don't fall.
- Torches always stand upright, even when placed on a wall. Furnaces show the same front on two sides.
- Mobs don't pathfind. They walk straight and hop up one-block steps.
- Free hosting forgets worlds when the server restarts (see the Render notes above).
- Day and night lighting is updated by the shader, but block light is recomputed only when a chunk is remeshed.
  That's instant for normal edits, but with many simultaneous edits there can be a short delay.
